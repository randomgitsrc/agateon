### 2.2 编号 12 — `agate-run.py` 遇 `*.log` 忽略恒返回 1

| 字段 | 内容 |
|---|---|
| **原始反馈** | 仓库 `.gitignore` 含 `*.log` 时，`agate-run.py --task` 写 `runs/<k>.log` 后被判 ignore，直接 `return 1` |
| **最终更正** | 无（该条在交接单中即为最终表述） |
| **当前状态** | **Confirmed**（`[实测]` 复现） |
| **适用范围** | **仅当项目 `.gitignore` 忽略 `agate-workspace/tasks/**/runs/**`**。Agateon 本仓 `.gitignore` **无 `*.log` 规则** ⇒ 本仓不触发 |
| **影响** | 白名单校验、证据落盘、账本事件**三样同时丢**（`return 1` 在 `_record_cmd_run` 之前）；且退出码与命令真实结果**相反**（命令成功 → agate-run 失败） |

**证据（`[实测]` 真实临时 git 仓库复现）**：

```
.gitignore:  *.log
             !agate-workspace/tasks/**/P6-evidence/logs/*
运行:        agate-run.py --task agate-workspace/tasks/TPVX-test "true"    # 命令是 true，必成功
输出:        agate-run: 任务内日志被 .gitignore 覆盖（证据须入库）: .../runs/1.log
             ——请在 .gitignore 加取反规则 `!agate-workspace/tasks/**/runs/**`
exit:        1
落盘:        runs/1.log 已写；gate-events.jsonl 不存在（0 行）
```

**四项配置矩阵**（`[实测]`）：

| `.gitignore` 配置 | `runs/1.log` 是否被 ignore | `agate-run` exit |
|---|---|---|
| 无 `*.log` 规则（= Agateon 本仓） | 否 | **0** ✅ |
| `*.log` + 仅 `P6-evidence/logs/*` 例外（= Peekview 本仓） | **是** | **1** ❌ |
| `*.log` + `!**/runs/**` 例外 | 否 | 0 ✅ |
| 目录级 ignore（`agate-workspace/**/runs/`） | **是** | **1** ❌ |

**性质判定**：这是**工具缺陷**，不是协议缺陷——但它**触发的条件很常见**（Python 项目普遍忽略 `*.log`）。
「证据须入库」这个**要求**是对的，问题在**实现方式**：把"忽略"当作**致命错误**并**在记账前 return**，
导致命令已成功执行却丢失全部记录。

**19/19 全线误报**。

任何修复方案若回到「gate 逐条比对 Then 子句」，就会被同一实验否证。**本报告不提出该方案。**

### 3.2 「Agent 犯错」≠「机制失效」

TPV0104 中多次出现 Reviewer 自我推翻、Verifier 重做验证、P7 探针推翻 P4 因果解释。
按交接单最终语气，这些应记为**正向质量信号**（独立评审 + 证据复核真的改变了错误结论），
**不转化为待修项**。核实：`P6.5-judge-verdict.md` 的 `status: passed` / `54/54` 与
`retrospective.md` 的 gate 拦截明细表均支持"错误在交付前被发现并修正"。

### 3.3 「Gate 拦截 10 次」不等于「10 次保障」

按 `retrospective.md` 的明细表自行分类（`[源码]` 原文数据）：

| 类别 | 次数 | 说明 |
|---|---|---|

## 6. 建议与优先级

> 原则：**只修被证据证明存在、且值得修的**。不因复盘而制造问题，不因保障而无限加流程。

### P1（建议修，真缺陷）

**① 第 11 条：把"P1 基线保护"义务补到 P2 评审环节**

- **最小方案**：在 `agate/assets/review-roles/plan-eng-review.md` 的「评审重点」增**一条**：
  「P2 的 schema/判定边界决策是否实质削弱某条 P1 BDD 的 Then 子句？若是，是否已按
  `[BASELINE_CHANGE]` 授权并回写 P1 正文？」——**不新增角色、不新增阶段、不新增 gate**
- **为什么不是 gate**：`[实测]` 逐条核对 Then 子句 → 19/19 误报（§3.1），已被实验证伪
- **为什么是 `plan-eng-review` 而非 P1**：P1 评审在 P2 之前，**结构上不可能**捕获 P2 造成的削弱
- **⚠️ 不要**顺手在 `rules/obligations.yaml` 加一条 R 义务：`[实测]` 当前 M 类占比
  `56/121 = 0.4628` 恰好等于基线，加一条 R（总数 121→122）会变成 `56/122` **低于基线**
  ⇒ `check-obligations.py` 直接 FAIL。若确需正式登记，必须**同时**给出 M 类补位方案，
  否则会把一条文档改动变成全量 pytest 红
- **验收条件（可判定，不写「必然提出」这种不可判定的标准）**：
  ① **正向**：构造「P1 要求字段必填 → P2 改为 nullable 且未改 P1 文本」的反例，跑一次 P2 评审，
     检查其输出里**是否出现针对该 BDD 的质疑**（出现 = 检查项被消费；不出现 = 未生效）；
  ② **反向**：构造「P2 明确写 `[BASELINE_CHANGE: 理由]` 并回写 P1」的正当演进，确认评审
     **不**判为违规（防「一律阻止变更」）；
  ③ 两次实验都只能抽样一次（LLM 评审非确定性），**结论按「至少一次命中」记，不承诺 100%**

**② 第 12 条：`agate-run.py` 不在记账前因 ignore 而 return**

- **最小方案**（二选一，取其一即可验证）：
  - (a) 把「日志被 ignore」从 `return 1` 降为 **WARNING + 继续记账**（命令结果与证据记录解耦——
    命令成功就是成功，证据入库失败是另一个可报告的问题）
  - (b) 保留 exit 1，但**先 `_record_cmd_run`** 再返回（至少账本不丢）
- **倾向 (a)**：退出码应反映**命令**的结果；"证据没入库"是**环境配置问题**，用 exit code 表达会
  让调用方误判命令失败（本任务 P5 verifier 因此退回裸 bash）
- **附带**：把 `runs/**` 与 `P6-evidence/logs/*` 同等对待（两者都是"证据须入库"的 agate 产出），
  并在 `agate-setup.py`/模板里给出 `.gitignore` 建议行
- **验收条件**：上述 4 项配置矩阵全部 `exit 0`（或 warns-only），且命令失败时仍 `exit != 0`

### P2（建议修，影响小但确定）

**③ 第 13 条：补全 `check-changelog.py` 右边界**

- **最小方案**：右边界补 `）`、`，`、`：`、`)`（半角右括号也缺）
- **必须保留**：左侧 `(^|[^0-9])`（防 `TAG0001` 误命中 `TAG00012`）
