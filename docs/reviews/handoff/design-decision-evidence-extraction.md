## 2. 已实现的规则（= 评审的候选规则）

```
1. 剥离反引号 code span（命令/代码注记多在其中）
2. 取全部括号组（全角/半角）
3. 组内按逗号（全角/半角）切分；去掉元数据项（vision: / ref: 前缀）
4. 剩余项「全部」是无空格路径 + 扩展名以字母开头 ⇒ 整组为证据引用组；否则整组为注记
5. 一行的引用 = 全部证据引用组的并集
```

**验证** `[实测]`：我的实现与评审 `extract-census.py` 在 1,774 行 PASS 上**逐行等价（0 差异）**。

## 4. 三个待裁定决策

### 决策 A：嵌套括号（#1–#5）——接受为已知边界，还是加规则覆盖？

**事实** `[实测]`：
- 两仓真实数据中「括号组含内层括号」的共 **26 处**；
- 这 26 处中，**没有任何一处**含真实存在的证据文件（0/26）；
- **评审的参考脚本同样取不到**（其 `GRP` 正则也不含内层括号）——所以这不是我实现偏离，是规则本身的边界。

**方案 A1（接受边界）**：维持现状。代价：这 26 处（**均为合成/演示形态**）取不到引用。
**方案 A2（加规则覆盖）**：允许括号组含一层内层括号，并从中提取路径片段。

> **⚠️ 本文 v1 在此处有一条失实自述，已删除（2026-10-03 独立评审查出）**：
> v1 写「我先前在交接文件中称『嵌套括号影响 17 行真的文件存在』，现更正为 0」。
> **核验结论：该声称不存在。** `git log --all -p -- docs/` 中与嵌套括号相关的
> **唯一出处就是本文自己**；交接文件从头到尾**没有**这个计数。
> ⇒ **我把一句自己从未说过的话当成「我先前说过」并去「更正」它**——
> 这比原先的错误更严重：**它凭空制造了一个不一致，再表演一次修正**。
> 连带 v1 里「这是我第二次犯按模式计数当结论（第一次是 `[-\w]*`）」的举证也建立在
> 这个不存在的事实上（`[-\w]*` 那次**是真实的**——见 §4-A 的历史记录）。
>
> **真实情况（据实重述）**：`[-\\w]*` 那次（设计 v2→v3）确实是我杜撰了缺陷前提，
> 由评审抓出；**本次 17 行是另一次杜撰**，两件事性质相同，但我**在 v1 里把第二次
> 描述成了"更正第一次没做过的事"**。已改为本节仅陈述**实测数字**，不作自我叙事。

### 决策 B：含空格的文件名（#7、#8）——放弃支持？

**事实** `[实测]`：两仓 **1,739** 个证据文件中，文件名含空格的 **0 个**。

**方案 B1（放弃，采纳评审建议）**：不容空格。改写 `test_evidence_md5_detail_2`，
在注释写明依据（0/1,739）。**符合 ADR-015「不为假想问题加改动」**。
**方案 B2（保留支持）**：加更强的区分判据（难度高——实测正是"容许空格"放进了
`Verified via x.py`、`scripts/ + WORKFLOW.md` 等散文）。

> **#8 需单独注意**：`bdd_9_chinese_filename` 用的是**含空格的中文名**（`截图 验证通过.png`）。
> 真实数据里非 ASCII 文件名存在（2 个），但**都不含空格**。新规则**能取不含空格的中文名**。
> ⇒ 若采纳 B1，该用例应改为**不含空格的中文名**（保住真能力），而非删除。

### 决策 C：「末组 = 证据」约定（#9）——改成"全部纯路径组"？

**事实** `[实测]`：
- 两仓 **1,160/1,774（65%）** 的 PASS 行含**多个**括号组；
- **非末组绝大多数是命令注记**（如 `` `ruff check agate/scripts/` exit 0 ``）；
- 我早期"取全部括号组"的尝试造成 **517 行多出引用、701 次解析不到**（已否决）；
- 但把判据收紧为「**整组都是纯路径**」后，评审回放显示**解析不到的只有 6 个**
  （且都是括号里的**源码文件名**，不是证据）。

**方案 C1（维持末组）**：保守。代价：漏掉**末组是注记、真引用在前**的行。
**方案 C2（采纳"全部纯路径组"，评审判 Q3「不合理」）**：覆盖更全。

> **C2 的风险必须量化**：改变 65% 行的判定口径 ⇒ **可能改变存量任务的 gate 结论**。
> 这正是 **R6 爆炸半径**要回答的，且必须是**差分**（评审对我的第 2 条纠正）。

## 6. 关于 R6 差分的说明（评审的第 2 条纠正，我接受）

评审指出我的"25 个新增拦截"**不是差分**（只跑了新代码，统计的是绝对数），且
**"全部是假红"不成立**（其中 `Verified via test_x.py` 属旧规则漏检的**真违规**）。

**我接受这两条纠正。** 正确的 R6 应是：

| 类别 | 含义 | 处理 |
|---|---|---|
| ① 假红 | 证据存在且引用正确，是提取/解析错了 | 修规则 |
| ② 旧规则漏检的真违规 | 如引用测试源码而非证据 | **可合并**，登记为历史已知违规 |
| ③ 无法判定 | 证据未入库，只能在作者本机核实 | 本机核实后归 ①/② |

**⚠️ 我尚未做这个差分**（本机可以做，因为两仓都在本机）。**建议在裁定决策 C 后立即做。**
