## W2 遗留：仍需修复

沿革说明第10行写"§3 补环境说明"，但实际 §3 与 §6 风险表均未见环境类型补充。这不是"修复质量不够"的问题，是**修复动作本身没有真正执行**——声明和实际内容不一致。

按本仓库既有纪律（评审报告落盘前需要核实声明与实际内容一致，参照本设计文档自己在 §7 事项7 体现的"不能仅凭自述就当作已验证"这条精神），这条不能因为"只是一条 WARNING、不阻断"就被默认忽略。

**修复建议**：在 §3 或 §6 风险表补充一句实测环境的基本描述，例如"本次实测环境为 {容器/物理机/CI，具体类型}，tmux 版本 3.4；若协议目标支持环境的典型 tmux 版本与此有差异，落地前需要在该版本上重新验证"。这条修复成本很低（一两句话），不需要重新做实机测试，只需要如实补充当时测试用的是什么环境。

**建议**：在正式提交立项（申领 RM 编号）之前，顺手补上 W2 这一句环境说明，成本极低；若暂不补，也应在 §7 待确认事项里明确登记这条待办，而不是让沿革说明里"已改"的表述继续误导读者以为四项问题已经全部清零。
