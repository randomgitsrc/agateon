# 设计：关闭 trailer 守卫的 pre-commit 盲窗（RM-AG0094 后续）

> **状态**：设计｜**日期**：2026-09-29｜**触 SELF-GATE**
> **来源**：`self-gate-tag0048` 评审查明——`test_selfgate_trailer_integrity.py`（#382 落地）
> **只在提交之后生效**，故「写报告 → amend」这套流程无法靠它自保。本缺陷**已复犯 5 次**。

---

## 1. 盲窗的机制（评审查明，我已复核）

| 阶段 | 能拿到 commit message？ | 守卫能否判定？ |
|---|---|---|
| `pre-commit` | ❌ **不能**（message 尚未存在） | ❌ |
| `commit-msg` | ✅ **能**（hook 参数即 message 文件路径） | ✅ |
| 提交后（CI / 测试） | ✅ | ✅（**但为时已晚**——已生成一个幽灵留痕的提交） |

`test_selfgate_trailer_integrity.py::commits_to_check` 取 `origin/main..HEAD`；**pre-commit 时该范围为空**
（HEAD 尚未成为新提交）⇒ 回退到 base ⇒ 而 base 无 trailer ⇒ **判据在 pre-commit 时恒绿**。
**⇒ 5 次复犯全部发生在这个盲窗里。**

---

## 2. 关键前提（实测）

要在 `commit-msg` 阶段判定「trailer 指向的报告是否存在」，须确认**那时报告已可见**：

| 形态 | 可见性 |
|---|---|
| 报告与代码**同一提交** | ✅ **在 index**（作者已 `git add`）——实测当前 index 含 `reviews/…tag0048…md` |
| 报告已在**历史提交**里 | ✅ 可 `git cat-file -e HEAD:<path>` |
| 报告**未暂存也未提交** | ❌ 不在 → **这正是要抓的幽灵** |

⇒ **判据（实现为准）**：`os.path.exists(磁盘)` **或** `git ls-files --error-unmatch`（index）。⚠️ **本文初稿此处写的是 `git cat-file -e :<path>`，与实现不符**——独立评审 F7 指出，已更正为实际实现。
三者皆无 = 幽灵。**注意必须查 index**——只用 HEAD 会把「同提交的报告」全部误判为缺失。

---

## 3. 设计：把存在性校验**前置到 commit-msg**，且**同时修一个既有缺陷**

### 3.1 为何不是「让 `--base` 回退到父提交」

另一条可行路是改 `commits_to_check` 的回退逻辑。**否决理由**：它仍只能**事后**（提交已存在）判定，
治的是"范围取错"，不是"时机太晚"；**幽灵留痕已经产生**。而 commit-msg **在提交被创建之前**就能拦。

### 3.2 落点：`commit-msg-self-gate.py`（已有该 hook 与校验函数）

该文件**已有** `_review_path_exists(path, root)` 与 `_check_review_path()`（#380 落地的存在性校验），
**但只 WARNING 不拦截**（其契约是提示型永不断 commit）。本设计**不破坏该契约**：

| 项 | 决定 | 理由 |
|---|---|---|
| 是否阻断 | **仍不阻断（WARNING）** | ⚠️ **重要**：稳定版 hook（`~/.agate/v0.76.0`）**没有**这次改动，用户装上的是旧版 ⇒ 若设计成阻断，**新旧版行为不一致**会造成"本机过、别人不过"。且本仓 hook 的既有契约是提示型。**改成阻断属独立决策，不在本条内。** |
| 那盲窗关掉了吗 | **关了**——判定**在提交前**发生 | 关键不是"阻断"，而是**在正确的时机给出告警**：作者当场看到 ⇒ 可立即 `git add` 报告重试。**CI（已有测试）是第二道网，负责不让它进 main。** |
| 判据来源 | **与 #382 守卫共用一份实现** | 避免两处判据漂移（本仓 DEBT0046 的教训：判据只能有一份） |

**⇒ 本设计=「同一判据 + 两个时机」**：commit-msg（即时告警，人可当场修）+ CI 测试（阻断进 main）。

### 3.3 同时修一个既有缺陷：trailer 的**路径 vs 清单**歧义（实测）

存量扫描发现 **8 条**历史 trailer **不是路径**，而是**被评审文件清单**：

```
self-gate-review: README.md, README.zh-CN.md, CHANGELOG.md, agate/UPGRADING.md
self-gate-review: agate/scripts/install-hook.py, agate/scripts/agate_common.py, ...
```

`_REVIEW_RE`（`^self-gate-review:\s*(\S+)`）只取**第一个 token**，于是把 `README.md` 当成报告路径 ⇒
**对这类写法误报**（#382 守卫用的是同一正则，只因范围只扫新增提交才没炸）。

**修法（不改变既有约定的合法写法）**：判定「**该 trailer 是否意在指向报告**」——

- 取 trailer 的**全部** token（按逗号/空白切分）；若**其中任一个**指向存在的文件 ⇒ **通过**
  （兼容"清单式"写法：清单里的文件通常都存在）；
- 若**全部** token 都不存在 ⇒ 告警（幽灵），并把它们**逐条列出**。

**为何这样定**：① 不新增语法、不改既有合法写法（零迁移）；② 幽灵留痕的本质是「声称的留痕**一个都找不着**」，
逐条列出可让作者立刻看出是路径写错还是报告没 `git add`；③ 与 #382 守卫**同源**，两处行为一致。

## 4. 验收锚（全部可测）

- [ ] commit-msg 阶段：trailer 指向**未暂存且未提交**的文件 → **输出告警**（exit 仍 0）
- [ ] commit-msg 阶段：报告**已暂存**（index）→ **无告警**（防把正常流程误报——这是本设计关键边界）
- [ ] commit-msg 阶段：报告在**历史提交**里 → 无告警
- [ ] **清单式写法**（多文件、逗号分隔、均存在）→ 无告警（修既有歧义）
- [ ] 全部 token 皆不存在 → 告警**逐条列出**
- [ ] `self-gate-skip:` → 不做路径检查（既有行为不变）
- [ ] **负向控制（重放 5 次复犯形态）**：构造「trailer 指向新报告但报告未 `git add`」的提交 →
      commit-msg 阶段告警；`git add` 报告后重跑 → 无告警
- [ ] 判据与 #382 守卫**同源**（同一个函数），有测试断言二者对同一输入结论一致
- [ ] 全量 pytest 全绿 + consistency 0 ERROR

## 5. 明确边界（不越界声称）

1. **本设计不把 hook 改成阻断**（§3.2）：故它**不能阻止**幽灵提交被创建，只能**当场告警**。
   **真正拦住进 main 的是 CI 里的 #382 守卫**——本设计补的是**时机**，不是**强制力**。
2. **不改触发面判定**（`_REVIEW_RE` 仍锚定行首 `self-gate-review:`）；但**改了它的取值面**（`(\S+)` → 整行值），本文初稿的「不改 `_REVIEW_RE` 的匹配面」表述**不准确**（F7）。
3. **不追溯**那 8 条历史清单式 trailer（§3.3 的修法已使其自然通过）。
4. **不做**：`--base` 回退改造（§3.1 否决）、把守卫扩到全历史（成本高、且历史不是本条目标）。
