# 实验需求：TAG0050 任务数据契约

> 设计文档：`design-tag0050-task-data-contract.md`。
>
> 本文件只登记**设计里还没验证过的断言**，以及验证它们的实验。实验在对应批次的 P2 结束前完成；做完后把结论写回设计文档，并修正相应的标注。

## E1：各平台下 append 对象值时的引号问题（批 B）

- **断言** `[待测]`：`k=v`、`--json`、stdin 这三种写法里，至少有一种能在 Claude Code、OpenCode、Codex、DSH 四个平台上被 agent 一次写对。
- **方法**：
  - 在每个平台上，让 subagent 按卡片说明，向一个副本任务追加 5 条 `results`；
  - 这 5 条要覆盖三种情况：证据路径里有空格、`text` 里有中文、列表元素里有逗号；
  - 记录每种写法的首次成功率、出错类型和重试次数。
- **判据**：每个平台至少有一种写法首次成功率 ≥ 4/5。达不到就回到设计 §3.4，补一个"按模板文件追加"的写法。

## E2：结构化写入的往返成本（批 D 之前）

- **断言** `[推断]`：和"写散文 → gate 失败 → 回退"相比，"命令写入 + 写入时当场校验"的派发轮次和 token 消耗不会更高。
- **方法**：
  - 选一个已完成、BDD 数 ≥ 20 的 P6；
  - 在副本上让 verifier 用两种方式各产出一次：一次按现行格式，一次用 `results` + set 工具；
  - 记录：派发次数、gate 失败次数、产出体量、耗时。
- **判据**：
  - 第二种方式的 gate 失败次数，不能多于第一种；
  - token 消耗如果高出 20% 以上，要在设计里登记为代价，并评估怎么精简。

## E3：T1 绊线的误报抽样（批 B 启用 ERROR 之前）

- **断言** `[推断]`：按设计 §3.6 的口径，存量语料中的命中行基本都是"按旧习惯写的真实声明"，引述或讨论类的误报为 0。
  - 口径：`default` 行首，只看正向标记；排除围栏代码块、行内代码、以反引号开头的行。
  - 命中行数：agateon（v0.79.0）393 行，peekview 233 行（repro-tag0050.sh 的 T1 段）。
- **方法**：
  - 两个仓库各随机抽 50 条命中行，人工分为两类："真实声明"和"引述 / 讨论 / 否定"；
  - 抽样脚本和分类结果入库，放在 `docs/research/`。
- **判据**："引述 / 讨论 / 否定"类为 0 条。不为 0 时：
  - 先调整排除规则，重新抽样；
  - 或者把出现误报的文件类型（例如 P7 评审稿）降级为 WARNING，并在设计里写明。

## E4：CI 回放耗时（批 A2）

- **断言** `[待测]`：按设计 §2.4 逐提交回放 pre-commit，在 agateon 的典型 PR 上，耗时处于可接受范围。可接受的标准是：不超过现有 `protocol-tests` 最慢 job 的耗时。
- **初值** `[自述，R4 评审实测]`：按设计 §2.4 规格，在 merge-base 协议下同时回放 pre-commit 和 commit-msg，TAG0042 的 16 个非合并提交全部 rc=0，单个耗时 0.13–1.89 秒，合计约 15 秒。实现中尚未包含 `AGATE_REPLAY`，因此实现后需要复测。
- **方法**：
  - 取 TAG0042 的 PR（`a68d763..720c97d3`，16 个非合并提交）；
  - 取一个只改一个任务、提交数少于 5 的 hotfix 类 PR；
  - 在副本上运行改造后的 `agate-ci-verify --base`；
  - 记录：被回放的提交数、总耗时、单提交耗时的分布。
- **判据**：TAG0042 规模的 PR 回放耗时不超过上述上限。若超出，在设计中登记以下改进（二选一）：
  - 只回放"改动了 `.state.yaml` 或阶段产出"的提交；
  - 按任务并行回放。
