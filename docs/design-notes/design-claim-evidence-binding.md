### 1.1 为什么放弃（**这是三次尝试的共同教训**）

评估 §2.2 的三分法早已给出答案，**我两次都在违背它**：

| 错误种类 | 该由谁抓 | 我两次的做法 |
|---|---|---|
| **判断类**（假前提、假阳性、抄错数） | **独立评审** | ❌ 试图做成机械判据 ⇒ **必然退化为仪式** |
| 结构类（漏登记、格式） | 机械判据 | — |

**评估 §1.1 的 10 处错误全部是判断类**（我推错、看漏、抄错）⇒ **不存在能抓住它们的机械判据**；
任何"机械版"的落点都只能是**关于声称的元数据**（有没有标记/有没有节），而元数据**可以空着写**。

**⇒ v3 不再尝试机械化判断。改为修一个真缺陷 + 把纪律绑到真正抓得住它的角色上。**

## 2. v3 要解决的真缺陷（**实测，非推理**）

### 2.1 缺陷：声称载体的改动**绕过全部检查**

`protocol-tests.yml:97` 的 docs-only 判定把 `agate-workspace/roadmap/`、`agate-workspace/debt/`、
`docs/`、`CHANGELOG.md` 视为 docs ⇒ **7 个 job（pytest/platform-scan/shellcheck/ruff/consistency/gate-backstop）全部 `needs: detect-docs-only` 并在 docs-only 时早退**（`:105-292` 实测）。

**而这三处正是我 10 处错误里 6 处的载体**：

| 载体 | 载体提交中无 trailer 的比例（近 40 非合并提交，实测） |
|---|---|
| `agate-workspace/roadmap/roadmap.md` | **43.8%** |
| `CHANGELOG.md` | 4.3% |
| 评审报告（`reviews/*.md`） | 0%（本身即评审产物） |

⇒ **一个只改 roadmap 的提交：无 SELF-GATE（无 trailer）→ 无独立评审；且 `protocol-tests.yml` 的 7 个 job 全部早退。**

**⚠️ 三处事实更正（v3 初稿夸大，独立评审指出，我已逐条实测复核）**：
1. **`consistency` 其实早已在跑**：`docs-check.yml:19` 的 `paths:` **包含** roadmap/debt/CHANGELOG，其 `:46` 跑
   `check-protocol-consistency.py --strict-errors-only`——与 `protocol-tests.yml:271` **同一条命令**。
   实测 5 个目标提交的 `docs-consistency` check-run 均为 `success` ⇒ **「无任何机械检查」是错的**。
2. **`gate-backstop` 永远 SKIP**：`ci-gate-backstop.py:131-133` 在无 `.state.yaml` 时 `return 0`；
   实测 `GITHUB_ACTIONS=true python3 agate/scripts/ci-gate-backstop.py` → `SKIP: 无 .state.yaml`（exit 0）。
   根 `.state.yaml` 不入库（`3d6dc8a` 起 gitignore）⇒ **它对这些提交是恒绿的空转**，修复 A **不**因此受益。
3. **pytest 对「声称内容」零覆盖**（决定性实测）：向 `roadmap.md` 注入
   `**实测覆盖率 99.9%（命令 python3 agate/scripts/does-not-exist.py）**` → 相关测试 **41 passed**，未被发现。
   ⇒ 修复 A 的 pytest 增益**不是**「抓住声称」，而是**结构/残留类检查**（如 `test_no_legacy_residue`）。
`595132b`（含"RM-AG0086/0089"这类已被撤销的声称）就是这样的提交——**它现在是 HEAD**。

### 2.2 修复 A（**客观、可测**）：让声称载体的改动**跑真检查**

**最强论据（我自查发现，比「声称无人查」更具体）**：`#382` 刚建的 `test_selfgate_trailer_integrity.py`
（防「self-gate-review 指向不存在文件」）**只在 pytest 运行时才生效**——而只改 roadmap / debt / CHANGELOG 的 PR
**走 docs-only ⇒ pytest 跳过 ⇒ 那道守卫在这些 PR 上根本不跑**。
⇒ **修复 A 直接补上我刚引入的守卫的覆盖漏洞**，不是泛泛地「多跑点检查」。
（配套实测：`gate-backstop` 对这些提交仍会 SKIP——因其无 `.state.yaml`，属**正确**行为；
故修复 A 的真实增益 = `pytest` + `consistency` + `platform-scan` + `ruff` + `shellcheck` 真实运行。）

把 `agate-workspace/roadmap/`、`agate-workspace/debt/`、`CHANGELOG.md` **移出 docs-only 白名单**
（`docs/` 与 `site/` 保留为 docs——它们**不是协议声称的载体**）。

**效果（可测）**：
- 影响面实测：近 60 个非合并提交中，docs-only 由 **11 → 3**（8 个转走全量）；
- **真实增益 = `pytest` + `shellcheck` + `platform-scan` + `ruff`**（**不含** consistency——它早已在跑，见 §2.1 更正 1；
  **不含** gate-backstop——恒 SKIP，见更正 2）；
- **populations 定位证据（表述已按评审判定更正）**：**凡是「无 trailer 的声称载体提交」都落在新走全量的集合里**
  （`595132b` / `d481b69` / `44ae94a` / `7dfefad` / `56f7a5c` 等）。
  ⚠️ **但这不是「修复 A 能帮到它们」的论据**——trailer 缺失不是修复 A 检测的东西；
  它只证明**修复 A 打中的是与问题重叠的人群**。**两个集合都是 8 个但并非同一个 8**（评审指出我的「恰好包含」写法不准确）。
**这就是"客观自动"的部分**——不判断声称真假，但**不再让声称载体处于无人检查的状态**。

**代价与更便宜的替代（评审建议，我采纳为默认方案）**：
- 全量代价：~20s（早退）→ **~2.5min**（pytest 是全部增量——consistency 早已在跑、gate-backstop 恒 SKIP）。
- **更便宜的规则（推荐）**：`detect-docs-only` 增设 `carrier_touched` 输出，仅**定向运行相关守卫**
  （`test_no_legacy_residue.py` + `test_selfgate_trailer_integrity.py` 等载体相关用例）⇒ **秒级而非 2.5min**。
- **我的取舍（2026-09-29 定稿）：本批**不做**修复 A**。经三处更正后其真实增益仅剩「结构/残留类检查」，
  而成本 2.5min/PR ⇒ 价值不足以在本批承担；**记录在案**，待有数据（如残留类缺陷复发）再启用。
  **若将来启用，优先采用便宜规则**（`carrier_touched` 定向守卫，秒级）而非全量。

### 2.3 修复 B（**纪律绑到真正抓住它的角色**）：评审角色 A 清单加一项

v1/v2 都漏掉了 RM-AG0094 anchor 的**另一半**：「评审角色的检查单含『本批是否有发现类声称未附命令』」。
**这是唯一能覆盖四类载体的机制**——因为评审报告是**唯一**在同一处通读 roadmap + debt + CHANGELOG + diff 的产物。

具体：`agate/assets/review-roles/protocol-alignment-review.md` 的 **A1–A7 清单**加 **A8**：

> **A8 声称-命令绑定**：本批新增/变更的**数字或结论类声称**（roadmap / debt / CHANGELOG / 本报告内），
> 逐条给出**产出它的命令**；**无法给出命令的声称，应删除该声称**（而非标注"不可复核"——标注保留了错误信息）。

**为何这不只是散文（与 v2 的区别）**：它不要求"写一个节"（那 2 行即可敷衍），而是**逐条回答清单项**，
且回答对象是**评审者**（其职责单一、且评估实证：独立评审抓出了全部 10 处错误）。
**但不撒谎**：它**仍是散文纪律**，只绑在正确的角色上。**其效力上限 = 评审者的尽责程度**
（评估 §2.3 已证：散文纪律会复发）——故 **A8 的价值是"把已知的失败模式写进职责"，不是"保证不复发"**。

### 2.4 机械守护（**只**守护「清单项存在」，不假装守护「回答质量」）

**采纳评审建议：不新增 SG.10，改为扩展既有 SG.2** —— 因为 `SG.2` 本就断言角色文件的 A 清单存在，
而它**当前只查 A1-A6、已漏 A7**（实测：函数名 `test_sg_2_role_file_has_a1_a6_checklist`）。
再为 A8 单开 SG.10 会造成**同类守护两套标准**；正确做法是把 SG.2 扩到 **A1..A8**。

**⚠️ 传播面（评审指出，实测 6 处）** —— 加 A8 必须同步这些「A1-A7」字样，
**否则 A8 自己就会制造该角色专门用来抓的那种漂移**：

| 位置 | 内容 |
|---|---|
| `SELF-GATE.md:70` | 成果文件描述「（A1-A7）」 |
| `SELF-GATE.md:128` | 「逐项检查 A1-A7」 |
| `SELF-GATE.md:161` | 「A1-A7 结论汇总表」 |
| `SELF-GATE.md:188` | 「逐项检查 A1-A7」 |
| `SELF-GATE.md:237` | 「对照 A1-A7」 |
| `protocol-alignment-review.md:133` | 「审查报告含 A1-A7 七项」 |
| `test_protocol_alignment_review.py` SG.2 | 扩为 A1..A8（**顺带补上漏掉的 A7**） |

**边界（不变）**：SG.2 证明的是「条文在」，**不是**「A8 被认真执行」——后者不可机械化（§1.1）。
故 **§2.3 不得暗示 SG.2 给 A8 增加了强制力**（评审要求）。

## 3. 明确的能力边界（**v1/v2 都在这条上出问题，故逐条写死**）

1. **v3 不判断声称真假**，不检测散文语义（v1 已实测：36% 误报）。
2. **修复 A 只保证「声称载体不再绕过检查」**——它保证的是**检查被执行**，不是**声称被验真**。
3. **修复 B 是散文纪律**，绑在评审角色上。**它可能复发**（评估 §2.3 的实测就是这个结论）。
   **本设计不声称它可靠**——只声称它比"藏在 `AGENTS.md` 第 126 行"更靠近使用点。
4. **`self-gate-skip:` 是既有逃生门**（历史 156 次）：v3 **不关闭它**（那属另一条）。
   故「有 trailer」不能当"已评审"的充分证据。
5. **不追溯存量**（60 done / 41 closed / 历史 roadmap 行）。
6. **不做**：通用命令注册表、语义声称检测、改 `done` 状态机（RM-AG0096）、在 `check-debt.py` 旁另立债务规则（RM-AG0088）。
